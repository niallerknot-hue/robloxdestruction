## Roblox facts relied on (Round 1)

1. **Voxel Resolution (4 studs)**:
   - *Fact*: `workspace.Terrain:WriteVoxels` and `WriteVoxelChannels` require `resolution == 4`. Any other number raises a runtime error.
   - *Source*: Roblox Creator Documentation: `Terrain:WriteVoxels` / `Terrain:WriteVoxelChannels`. Verified in `build/globalTypes.d.luau`.
2. **Region Grid Alignment**:
   - *Fact*: Regions passed to `WriteVoxels` and `WriteVoxelChannels` must align to 4-stud boundaries, achieved via `Region3:ExpandToGrid(4)`.
   - *Source*: Roblox Creator Documentation: `Region3:ExpandToGrid`.
3. **Voxel Call Ceiling (4,194,304 voxels)**:
   - *Fact*: A single terrain write cannot exceed 4,194,304 voxels. Chunking the map into slices of 40 × 40 × 22 voxels (35,200 voxels per slice) operates well below this limit and allows yielding via `task.wait()`.
   - *Source*: Roblox Engine Documentation / Developer Forum.
4. **3D Array Dimension Order (`[x][y][z]`)**:
   - *Fact*: Materials and occupancy arrays must match the region's voxel count along each axis and index in `[x][y][z]` order.
   - *Source*: Roblox Creator Documentation: `Terrain:WriteVoxels`.
5. **Shorelines Liquid Channel (`LiquidOccupancy`)**:
   - *Fact*: In the Shorelines terrain system, water is stored in the `LiquidOccupancy` channel written via `Terrain:WriteVoxelChannels(region, 4, { SolidMaterial = ..., SolidOccupancy = ..., LiquidOccupancy = ... })`. Voxels containing pure water must specify `SolidMaterial = Enum.Material.Air` and `SolidOccupancy = 0`.
   - *Source*: Roblox Creator Documentation: `Terrain:WriteVoxelChannels` and Shorelines API reference.
6. **Material Enums**:
   - *Fact*: Roblox's standard material for soil/dirt is `Enum.Material.Ground` (`Enum.Material.Dirt` does not exist in Roblox Luau API).
   - *Source*: `build/globalTypes.d.luau` line 4019 and Selene standard library definitions.

### Roblox facts relied on (Round 2)

1. **`Players.CharacterAutoLoads`**:
   - *Fact*: `Players.CharacterAutoLoads` is a server-side boolean property. Setting it to `false` disables Roblox's default behavior of automatically spawning a character model for players upon joining or respawning. Setting it back to `true` re-enables automatic spawning on future character respawns.
   - *Citation*: Roblox Creator Documentation: `Players.CharacterAutoLoads` ("Determines whether player characters should automatically respawn upon joining or after dying. Defaults to true. Setting this property to false allows developers to implement custom spawning logic").
2. **`Player:LoadCharacter()`**:
   - *Fact*: Calling `player:LoadCharacter()` from a server Script immediately initiates spawning of the player's avatar into Workspace and fires the `CharacterAdded` event signal.
   - *Citation*: Roblox Creator Documentation: `Player:LoadCharacter` / `Player:LoadCharacterAsync` ("Loads the character for the player. Can only be called on the server. If CharacterAutoLoads is disabled, this is used to manually spawn the player"). Verified in `build/globalTypes.d.luau` (line 15937).
